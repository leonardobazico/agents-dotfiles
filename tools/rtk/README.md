# rtk

[rtk](https://github.com/rtk-ai/rtk) is a CLI proxy that condenses command output
before an agent reads it. Verified against rtk 0.50.0.

## Owned

| File | Stows to | Effect |
|------|----------|--------|
| `codex/hooks.json` | `~/.codex/hooks.json` | `PreToolUse` hook on `Bash`, running `rtk hook codex` |

`setup-rtk.sh` installs rtk's own integrations. `tests/` covers both and is
repository-only.

## Named, not owned

These surfaces are rtk's but live elsewhere. Change them where they are.

| Surface | Location | Owner |
|---------|----------|-------|
| `PreToolUse` entry `rtk hook claude` | `harnesses/claude/settings.json` | written by `rtk init`, committed |
| `Running Commands` section | `shared/agents-md/AGENTS.md` | hand-written |
| OpenCode plugin | `~/.config/opencode/plugins/rtk.ts` | generated by `rtk init --global --opencode`, not versioned |
| History and recall databases | `~/Library/Application Support/rtk/` | rtk, machine-local |

## Why it is set up this way

**Claude init is `--hook-only`.** `setup-rtk.sh` runs
`rtk init --global --hook-only --auto-patch --agent claude`, not plain
`rtk init --global`. Plain init appends an `@RTK.md` reference to
`~/.claude/CLAUDE.md`, which is this repo's hand-maintained
`shared/agents-md/AGENTS.md`. The agent-facing rules live in that file's
`Running Commands` section instead, written by hand and committed.

**rtk patches `settings.json` through the stow symlink**, so its `PreToolUse`
entry lands in `harnesses/claude/settings.json` and is committed like any other
Claude Code write. Uninstalling leaves `"PreToolUse": []` behind; drop that hunk
by hand if it matters.

**`hooks.json` is committed rather than generated.** `rtk init --global --codex`
does register a real PreToolUse hook, but it also writes `~/.codex/RTK.md` and
appends an `@<absolute path>/RTK.md` line to `~/.codex/AGENTS.md`. That file is
the stow symlink, and rtk writes through it into `shared/agents-md/AGENTS.md`.
Reproduce with a sandboxed `CODEX_HOME` whose `AGENTS.md` is a symlink:

```
printf 'y\n' | HOME="$sandbox" CODEX_HOME="$sandbox/.codex" rtk init --global --codex
tail -1 "$sandbox/src/AGENTS.md"     # @/abs/path/.codex/RTK.md
```

The path it writes is machine-absolute, so a committed copy breaks on any machine
with a different username. There is no escape hatch either:

```
rtk init --global --codex --hook-only   # rtk: --codex cannot be combined with --hook-only
rtk init --global --codex --auto-patch  # rtk: --codex cannot be combined with --auto-patch
```

Fifteen committed lines are cheaper than that.

**The Codex hook needs trust approval.** Codex treats a non-managed hook as
untrusted until you approve it in a session with `/hooks`; linking does not
bypass that, so a freshly provisioned machine has the symlink in place and the
hook inert until you approve it once. Approval is recorded in `~/.codex/config.toml`
under `[hooks.state]` as a `trusted_hash` of the hook definition, so editing
`codex/hooks.json` invalidates it and Codex asks again.

**`rtk hook codex` is the native processor.** It emits `updatedInput` plus
`permissionDecision: "allow"`. It writes nothing and exits 0 when the payload
omits `permission_mode`, which Codex supplies on turn-scoped events. An earlier
Python shim reimplemented this by post-processing `rtk hook claude`; rtk 0.50.0
made it redundant. `tests/codex_hook_contract_test.sh` fails loudly if that
contract changes.

**Backup archival in `setup-rtk.sh`.** `rtk init` overwrites
`~/.claude/settings.json.bak` unconditionally, and that path holds the
pre-migration original `scripts/restore-harness.sh` hands back on unlink. The
script archives it as `settings.json.bak.<UTC timestamp>.pre-rtk` and archives
rtk's own snapshot as `settings.json.bak.<UTC timestamp>.rtk`. Both paths are
printed, including after a failed or interrupted init. Archiving refuses
overwrites; on failure the source is retained and its location reported. These
timestamped backups require manual restoration: `unlink-tools` only restores the
exact `.bak` name.

**Teardown needs the binary.** `make teardown-rtk` fails if rtk is absent, because
it runs `rtk init --uninstall`. Reinstall rtk first.

**Verifying a prose change.** `codex debug prompt-input` renders the model-visible
prompt without an API call. It also confirms Codex does not expand `@` references
in `AGENTS.md`, absolute or relative, which is why the `@RTK.md` line that
`--codex` writes is text no Codex agent reads.

**If rtk is absent**, both hooks invoke a command that does not resolve, and the
shell returns 127. Claude Code blocks a `PreToolUse` tool call only on exit code 2
or an explicit `permissionDecision: "deny"`; every other non-zero exit is a
non-blocking error and the tool call proceeds. So an rtk-less machine gets raw
output and a hook warning, not blocked commands. `make link-all` stows
`harnesses/claude/settings.json` and therefore its hook entry, so that state is
reachable without ever running `make setup-rtk`; the Codex hook is not, because
tool packages stay out of `link-all`.
